# М-Комплекс — СОП, тарификация и сдельный расчёт труда

MVP-прототип модуля расчёта труда для системы управления молочной фермой «М-Комплекс».
Данные хранятся в **локальном SQLite** (`data/m-complex.db`), бизнес-мутации выполняются
через **Express API** (`/api/v1`). Один файл БД — достаточно для развёртывания у клиента;
API слушает `0.0.0.0`, к нему можно подключиться по локальной сети.

Это **не** производственный модуль качества СОП. Здесь СОП — только источник тарифицируемых
операций; сам факт выполнения приходит из уже существующего производственного контура.

## Запуск

```bash
npm install
npm run dev:full
```

- UI: `http://localhost:5174` (и `http://<ip-машины>:5174` в LAN)
- API: `http://localhost:3001` (`GET /health`, `GET /api/v1/state`)
- БД: файл `data/m-complex.db` (создаётся и сидируется при первом запуске API)

По отдельности:

```bash
npm run api          # Express + SQLite на :3001
npm run dev          # Vite UI на :5174 (проксирует /api на API)
```

После `npm run build` можно отдать UI тем же API:

```bash
npm run build
npm run start        # API + статика из dist/
```

Дополнительно:

```bash
npm run typecheck
npm run preview
```

`npm run dev` идёт через обёртку `scripts/run-vite.mjs`: если в системе лежит заранее
подготовленный `%LOCALAPPDATA%\esbuild-bin\esbuild.exe`, скрипт подставит его в
`ESBUILD_BINARY_PATH`. Это нужно там, где postinstall esbuild блокируется политиками; на обычной
машине шим ничего не меняет.

Стек: React 18 + TypeScript, Vite 5, Tailwind CSS 3, React Router 6, Express 5,
better-sqlite3. Состояние — общий `appReducer` на сервере; фронт загружает и обновляет
через REST.

## Хранение данных

Таблицы 1:1 с доменом: `persons`, `divisions`, `sops`, `sop_facts`, `sop_fact_performers`,
`work_plan_items`, `sop_tariffs`, `timesheet_periods`, `timesheet_entries`, `timesheet_lines`,
`period_coefficients`, `bonus_penalties`, `app_meta` (роль демо-переключателя).

- `GET /api/v1/state` — полное состояние приложения
- `POST /api/v1/action` — тело = `AppAction` из UI; сервер применяет reducer и пишет SQLite
- `POST /api/v1/reset` — пересидировать демо-данные

Переменные окружения API (опционально): `API_PORT` (3001), `API_HOST` (0.0.0.0),
`SQLITE_PATH`, `VITE_API_BASE` (пусто = относительные URL через прокси Vite).

## Бизнес-решения, зашитые в прототип

Эти решения зафиксированы заказчиком и не подлежат переинтерпретации в коде:

1. Оплата только сдельная. Оклад и повременная оплата не рассчитываются и не хранятся.
2. Единица измерения ставки задаётся в тарифе (операция, час, голова, домик, секция).
   Сумма позиции = количество факта × ставка тарифа.
3. Коэффициент действует на весь расчётный период целиком, а не на отдельную операцию.
4. Нет тарифа на дату факта → операция всё равно фиксируется, но сумма равна `null`
   (в интерфейсе «—»), а не нулю, и получает статус «Тариф не задан».
5. Лимитов и дополнительного согласования для премий и штрафов нет.
6. Основание премии или штрафа обязательно; ссылка на отклонение или задачу — опциональна.
7. Подразделение — это оргструктура, а не место содержания животных. Домик, двор и секция
   попадают в поле `objectLabel` производственного факта.
8. Табельная позиция создаётся автоматически из производственного факта. Ручной ввод — редкая
   корректировка с обязательным комментарием.
9. Тариф — отдельная сущность. Карточка СОП не содержит денежных полей.

## Структура проекта

```
src/

    store/
      seed.ts          сборка исходного состояния из mock-данных
      reducer.ts       все переходы статусов
      selectors.ts     производные данные для экранов
      StoreProvider.tsx
    navigation.ts      разделы меню и доступ по ролям
    AppShell.tsx       шапка с переключателем ролей, боковое меню
    App.tsx            маршруты
  entities/            доменные типы и mock-данные, по одной папке на сущность
  features/payroll/    чистые расчётные функции
  widgets/             таблицы, панели, модальные формы
  pages/               экраны модуля (включая календарный табель)
  widgets/
    timesheet-calendar/ матрица специалист × дата, popover дня
  shared/ui/           UI-примитивы

```

Правило разделения: **экраны ничего не вычисляют**. Любая арифметика живёт в
`features/payroll` и попадает в JSX уже готовым числом. Календарный табель — представление
над `TimesheetLine` / `SopFact` через селектор `selectCalendarMatrix` (новых сущностей нет).

## Доменная модель

Идентификаторы полей — английский camelCase, значения перечислений — английские,
все подписи и данные в интерфейсе — русские.

| Сущность | Файл | Назначение |
| --- | --- | --- |
| `Division` | `entities/division/model.ts` | Подразделение (оргструктура) |
| `Person` | `entities/person/model.ts` | Физическое лицо, роли демо |
| `Sop` | `entities/sop/model.ts` | СОП трёх уровней в одной иерархии |
| `SopTariff` | `entities/tariff/model.ts` | Тариф СОП, отдельно от карточки СОП |
| `SopFact` | `entities/sopFact/model.ts` | Производственный факт (вход) |
| `TimesheetPeriod` | `entities/timesheet/model.ts` | Табель периода (шапка) |
| `TimesheetEntry` | `entities/timesheet/model.ts` | Табельная запись сотрудника |
| `TimesheetLine` | `entities/timesheet/model.ts` | Табельная позиция |
| `PeriodCoefficient` | `entities/coefficient/model.ts` | Коэффициент периода |
| `BonusPenalty` | `entities/bonusPenalty/model.ts` | Премия или штраф |

Связи:

```
Division ──< Person ──< SopFact ──1:1── TimesheetLine >── TimesheetEntry >── TimesheetPeriod
Sop (L1) ──< Sop (L2) ──< Sop (L3) ──< SopTariff >── Division
TimesheetEntry ──< BonusPenalty
TimesheetPeriod ──< PeriodCoefficient ──> TimesheetEntry (divisionCoefficientId / personCoefficientId)
```

Расчётные поля (`суммаПоСделке`, `суммаПослеКоэффициентов`, `итогоКВыплате`,
`количествоОпераций_безТарифа`) намеренно **не хранятся** в сущностях: они вычисляются
на лету функцией `buildPayoutBreakdown`.

Инварианты выражены типами: `quantity: 1` — литеральный тип, `normUnit: "operation"` —
литерал, `amount: number | null` — null означает «решение о тарифе не принято».

## Где зашиты бизнес-правила

| Правило | Где в коде |
| --- | --- |
| Поиск тарифа на дату факта, приоритет должностного тарифа над общим, игнорирование черновиков | `features/payroll/applyTariff.ts` → `findApplicableTariff` |
| «Частично выполнено» и «Не выполнено» не создают табельную позицию | `features/payroll/buildTimesheet.ts` → `buildLineFromFact` (возвращает `null`); список статусов — `entities/sopFact/model.ts` → `PAYABLE_FACT_STATUSES` |
| Нет тарифа → `amount: null`, статус `tariff_missing` | `features/payroll/buildTimesheet.ts` |
| Пересчёт сумм после того, как тариф задан задним числом | `features/payroll/buildTimesheet.ts` → `recalcLineWithTariffs`, вызывается из `app/store/reducer.ts` (`recalcAllLines`) |
| Сумма по сделке без отклонённых позиций и без нулей за позиции без тарифа | `features/payroll/calcCoefficients.ts` → `calcPieceworkTotal` |
| Незаданный коэффициент = множитель 1,00 | `features/payroll/calcCoefficients.ts` → `coefficientValue` |
| Коэффициент на весь период | тип `PeriodCoefficient` без полей дат + `applyCoefficients` |
| Итого = после коэффициентов + премии − штрафы; отменённые начисления не считаются | `features/payroll/calcFinalPayout.ts` → `calcFinalPayout`, `sumAccruals`, `isAccrualCounted` |
| Строка формулы на экране | `features/payroll/calcFinalPayout.ts` → `buildFormulaText` |
| Округление до копеек в одной точке | `features/payroll/rounding.ts` → `roundKopecks` |
| Новая версия тарифа закрывает предыдущую днём раньше и отправляет её в архив | `app/store/reducer.ts`, кейс `tariff/approve` |
| Двухшаговое согласование тарифа | тариф всегда создаётся как `draft` (`tariff/createDraft`), в `active` переводит только роль `direction_manager` (`pages/TariffsPage.tsx`) |
| Снятие утверждения / архив / восстановление | `tariff/unapprove` (active → draft), `tariff/archive` (active → archived), `tariff/restore` (archived → draft). Нетиповые действия — в карточке `/tariffs/:id`; утверждение черновика — и в очереди списка, и в карточке |
| Комментарий обязателен при отклонении и ручной корректировке | `widgets/timesheet/LineDecisionModals.tsx` |
| Табель подразделения подтверждается только при отсутствии позиций в статусе `auto_generated` | `pages/DivisionTimesheetPage.tsx` → `canConfirmAll` |
| Календарный табель: ячейка = агрегат lines за дату; день = сумма amount ≠ null | `app/store/selectors.ts` → `selectCalendarMatrix` |
| Добавление операции из календаря = `SopFact` + автопозиция | `app/store/reducer.ts` → `fact/create` |
| Период утверждается только когда все подразделения подтверждены; после утверждения всё блокируется | `pages/PeriodApprovalPage.tsx` + `app/store/selectors.ts` → `isPeriodLocked` |
| Доступ по ролям | `app/navigation.ts` |

## Где менять mock-данные

Каждая сущность лежит рядом со своим типом:

| Что поменять | Файл |
| --- | --- |
| Подразделения | `src/entities/division/mock.ts` |
| Сотрудники и состав ролей демо | `src/entities/person/mock.ts` |
| Дерево СОП L1 → L2 → L3 | `src/entities/sop/mock.ts` (seed; runtime — `state.sops`) |
| Тарифы, включая историю версий | `src/entities/tariff/mock.ts` |
| Производственные факты (генератор) | `src/entities/sopFact/mock.ts` |
| Расчётные периоды | `src/entities/timesheet/mock.ts` |
| Коэффициенты периода | `src/entities/coefficient/mock.ts` |
| Премии, штрафы, справочник отклонений | `src/entities/bonusPenalty/mock.ts` |
| Демо-«сегодня» | `src/shared/lib/utils.ts` → `DEMO_TODAY` |

Табельные записи и позиции в mock-файлах **не лежат**: они собираются в
`src/app/store/seed.ts` из производственных фактов теми же функциями, что работают в рантайме.
Точечные исключения (подтверждённые позиции, одна ручная корректировка, одно отклонение,
полностью проверенный доильный блок) заданы в `applyDemoOverrides` там же.

Факты генерируются детерминированным LCG с фиксированным зерном, поэтому цифры одинаковы при
каждой перезагрузке. Чтобы поменять объём данных, правьте массив `plans` в
`src/entities/sopFact/mock.ts`.

Кнопка «Сброс демо» в шапке возвращает состояние к исходному.

## Маршруты

| Маршрут | Экран | Роли |
| --- | --- | --- |
| `/sops`, `/sops/:sopId` | Реестр СОП с деревом и карточкой операции | все |
| `/tariffs` | Управление тарифами, очередь утверждения, timeline | методолог, управляющий |
| `/tariffs/:tariffId` | Карточка утверждения тарифа (архив / восстановить / снять утверждение) | методолог, управляющий |
| `/my-operations` | Операции специалиста | специалист, бригадир |
| `/timesheet` | Табель подразделения (подтверждение, коэффициенты, премии) | бригадир, управляющий |
| `/timesheet-calendar` | Календарный табель операций (специалист × дата) | бригадир, управляющий |
| `/period-approval` | Утверждение периода | управляющий |
| `/payout/:personId` | Детальная карточка расчёта | все (специалист — только свой) |
| `/calc-check` | Проверка расчётных функций | все |

Роли переключаются в шапке. Если текущий раздел новой роли недоступен, происходит переход
на её домашний экран (`app/navigation.ts` → `defaultRouteForRole`).

## Сценарии для проверки

0. **Создание, правка, архив и смена уровня.** Роль «Методолог» или «Управляющий» → `/sops`.
   «Добавить СОП» / «Редактировать» / «В архив» / «Из архива». Код при создании подставляется
   автоматически. Уровень можно сменить, если нет дочерних узлов. Архивация каскадно уводит
   потомков; восстановление — только выбранный узел (родитель должен быть действующим).
   Архивные СОП не участвуют в новых тарифах и фактах.
1. **Тариф не задан.** `/sops` → «Контрольное взвешивание телёнка» — пустой блок тарифов
   и предупреждение. Затем `/my-operations` под ролью специалиста: строки этой операции
   подсвечены янтарным, сумма «—», в сводке есть счётчик «без тарифа».
2. **Тариф задним числом.** Роль «Методолог» → `/tariffs` → «Создать тариф» для
   `СОП-01.03.03`, подразделение «Телятник», дата начала `2026-08-01`. Затем роль
   «Управляющий» → «Утвердить». Суммы по этим операциям пересчитаются во всех экранах,
   счётчик операций без тарифа уменьшится.
3. **История версий.** `/tariffs` → строка «Выпойка ЗЦМ» → timeline: архивная версия
   80 ₽ до 31.07.2026, действующая 420 ₽ с 01.08 по 31.08.2026 и черновик 450 ₽ с 01.09.2026.
4. **Черновик не платит.** На `/calc-check` проверка «Черновик тарифа не даёт суммы
   до утверждения» показывает, что ставка 450 ₽ не применяется, пока управляющий не утвердил её.
   На `/tariffs` очередь «На утверждение» и кнопка «Утвердить» у черновика; нетиповые действия
   (архив, из архива, снять утверждение) — в карточке `/tariffs/:id`. Восстановление из архива
   возвращает тариф в черновик.
5. **Обработка табеля.** Роль «Бригадир» → `/timesheet` → развернуть сотрудника →
   подтвердить, отклонить (нужен комментарий) или скорректировать вручную (нужен комментарий).
   Кнопка «Подтвердить весь табель подразделения» станет активной, когда не останется позиций
   в статусе «Сформировано автоматически».
6. **Коэффициенты и начисления.** Телятник: коэффициент подразделения 1,00 (зарплата = выработка).
   Премия бригадиру 560 ₽ добивает сделку до 120 000 ₽. У Петровой — оспоренный штраф.
7. **Утверждение периода.** Роль «Управляющий» → `/period-approval`. Пока не подтверждены все
   подразделения, кнопка «Утвердить период» заблокирована. После утверждения строки получают
   иконку замка, а формы табеля становятся недоступны.
8. **Расчётная лента.** `/payout/per-kuznecov` — бригадир ~120 000 ₽; `/payout/per-petrova` —
   сделка ~85 000 ₽ (высокая выработка; оспоренный штраф снижает итог). Эталон на `/calc-check`:
   `84 500,00 ₽ (сделка) × 1,10 (коэффициент подразделения) × 1,05 (коэффициент сотрудника) + 5 000,00 ₽ (премии) − 2 000,00 ₽ (штрафы) = 100 597,50 ₽`.
9. **Самопроверка расчёта.** `/calc-check` — одиннадцать эталонных примеров. Те же результаты
   печатаются в консоль браузера при старте приложения.
10. **Календарный табель.** Роль «Бригадир» → `/timesheet-calendar`. Ячейки заполнены из
    фактов августа по графику 5–2 (в выходные — «·»). Hover/клик → popover с суммой дня.
    «Добавить операцию из СОП» создаёт факт и позицию; отклонение требует комментарий.
    Колонка «Итого» и нижняя строка — сделка без коэффициентов. После утверждения периода
    кнопки правок скрыты.

## Демо-данные

Период **август 2026**. Телятник: 4 оператора (Петрова, Сидоров, Волкова, Лебедева) + бригадир
Кузнецов. Сделка: бригадир 120 000 ₽, операторы ~62–86 000 ₽ по выработке.

График телятника: скользящий **5–2** (Петрова вт–ср, Сидоров чт–пт, Волкова сб–вс,
Лебедева вс–пн; бригадир пн–пт). На смене всегда ≥2 оператора; в воскресенье — ровно Петрова
и Сидоров. В смены — выпойка ЗЦМ и комбикорм; подстилка по понедельникам (или в ближайшую
смену); ~30–80 очисток домиков в месяц. Ставки: 420 / 350 / 480 / 700 ₽.

Также: родильное и доильный блок (короткий набор фактов), 11 операций L3 (добавлена «Выдача
комбикорма»), контрольное взвешивание без тарифа, timeline ЗЦМ и черновик на сентябрь.
